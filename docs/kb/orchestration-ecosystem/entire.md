# Entire records the session; tsk coordinates the work

Entire, as of October 2026, is two products from one company: an open-source, MIT-licensed Go CLI that captures each coding-agent session as a "checkpoint" in the user's own git repository and links it to the commit with an `Entire-Checkpoint` trailer, and, since 26 October 2026, a hosted git forge with "Trails" in place of pull requests, review agents that run in cloud sandboxes, and a memory layer. In the frame of the earlier analysis of Dify, n8n, Dust and StackAI, Entire is none of the three cleanly. It is not a deployment substrate, because it does not host or schedule the coding agent: "Coding agents are the developer's own", and the only agents Entire runs are review and evaluation jobs. It competes with tsk only at one edge, session trace-back and resume, where it goes further than tsk's session-ID trailer. It lacks the whole planning ledger: missions, objectives, tasks with claims, decisions, questions, actors, thread bindings and agent-neutral continuation entries. The fit is therefore as a capture-and-review layer under tsk: install the CLI in the Claude Code cloud container, and each commit a tsk robot makes carries a pointer to a full, queryable transcript beside tsk's own trailer. The obstacles are concrete and mostly untested: the cloud proxy's branch-only push rule against Entire's default `refs/entire/` namespace, a redaction pass that the default backend skips, a second set of agent hooks beside tsk's, and a company whose newer features assume that Entire hosts the remote.

## A $60 million seed bought a checkpoint CLI, then a forge

Entire was founded by Thomas Dohmke, CEO of GitHub for four years until August 2025, and announced on 10 February 2026 with a **$60 million seed at a $300 million valuation** led by Felicis, which called it "the largest seed round ever for a dev tool startup", with Madrona, M12, Basis Set and Datadog's Olivier Pomel among the participants ([TechCrunch, 10 Feb 2026](https://techcrunch.com/2026/02/10/former-github-ceo-raises-record-60m-dev-tool-seed-round-at-300m-valuation/)). The company's own post names further investors and states the mission: "build the world's next developer platform where agents and humans can collaborate, learn, and ship together" ([Hello Entire World](https://entire.com/blog/hello-entire-world)). The legal entity is "Entire Inc., Bellevue, Washington" per Dohmke's Deutsche Telekom board profile ([Telekom](https://www.telekom.com/en/about-us/corporate-governance/supervisory-board/profile-dr-thomas-dohmke)), while Seedtable lists Wilmington, North Carolina ([Seedtable](https://seedtable.com/companies/entire)); the notes leave that conflict unresolved. No source names a co-founder, gives a headcount or records a round after the seed. The domains entire.io and entire.com redirect to the same company.

The February vision had three parts: "a git-compatible database that unifies code, intent, constraints, and reasoning", "a universal semantic reasoning layer" for multi-agent coordination, and "an AI-native software development lifecycle" ([Hello Entire World](https://entire.com/blog/hello-entire-world)). Read against tsk, the first of those is close to what tsk's Dolt ledger already is. What shipped first was narrower. The CLI, `entireio/cli`, had about **5.3k stars and 11,051 commits** on 28 October 2026 ([GitHub entireio/cli](https://github.com/entireio/cli)) and reached v0.12.1 in late October ([newreleases.io](https://newreleases.io/project/github/entireio/cli/release/v0.12.1)). Its mechanism is two sets of hooks: "Agent hooks collect session context: prompts, transcript, tool activity, changed files, and token usage", and "Git hooks link that context to a commit ... adding an Entire-Checkpoint trailer" ([Docs: Capture checkpoints](https://docs.entire.com/guides/checkpoints/capture-checkpoints.md)). "Entire does not add commits to your branch"; checkpoints go to the remote, to a separate checkpoint repository, or nowhere with `--skip-push-sessions` ([README](https://github.com/entireio/cli)).

Storage is where Entire and tsk met the same problem. Since CLI 0.10.0 the default backend gives "Each checkpoint ... its own ref at `refs/entire/checkpoints/<shard>/<id>`", keyed by a 26-character ULID; the older backend keeps every checkpoint on one shared branch, `entire/checkpoints/v1`, and `entire doctor migrate-checkpoints` moves a repository from the branch to refs ([Docs: Session storage](https://docs.entire.com/guides/checkpoints/checkpoint-storage.md)). That is the reverse of tsk's path: tsk moved to custom refs (`refs/tsk/ledger`) for new repositories but keeps `refs = "branches"` because the Claude Code cloud proxy refuses any push outside `refs/heads/*`. Supported agents grew from Claude Code and Gemini CLI at launch to Claude Code, Codex, Cursor, Copilot CLI, OpenCode, Antigravity, Factory Droid and Pi in the core, with more through plugins and an Agent Integration Protocol ([README](https://github.com/entireio/cli); [Docs index](https://docs.entire.com/llms.txt)). Later releases added `entire blame` (lines traced to sessions), import of earlier agent history and subagent tracking for Claude Code ([Blog index](https://entire.com/blog)).

The centre of the company then moved. In July 2026 Dohmke argued that git hosting should return to a distributed network of hosts ([How Version Control Will Evolve for the Agent Boom](https://entire.io/blog/how-version-control-will-evolve-for-the-agent-boom)), and on 26 October Entire launched "the Git forge for agent-human collaboration" on "three primitives: Trails, distributed Git hosting, and Continuous Memory" ([Forge post](https://entire.com/blog/the-git-forge-for-agent-human-collaboration)). Hosting runs as native repositories or as mirrors of GitHub, so GitHub can stay the source of truth, in US, EU, Australia, India and UK regions. Trails replace the pull request with eval scores that update on each push, can start from a bug report, a feature request or an agent, span several repositories, and hold "the goal, decisions, and discussion", changes, sessions, findings, gates and CI results ([Trails](https://entire.com/features/trails)). Continuous Memory is two open-source, local-first CLI plugins, entire-graph and entire-brain, where brain can sync to an Entire backend for a team ([Forge post](https://entire.com/blog/the-git-forge-for-agent-human-collaboration)). Pricing is prepaid credit billed only for agent model tokens "at the model provider's rates", with a $100 trial credit, and "You can continue using other features for free" ([Docs: Billing](https://docs.entire.com/billing.md)). The CLI stays open source; no source confirms that the forge server is, despite Dohmke's "full stack open source" reply on Hacker News ([HN item via Algolia](https://hn.algolia.com/api/v1/items/46961345)). The forge was two days old when the notes were taken, and no independent technical review of it exists yet.

## Entire attaches to agents that run elsewhere, so it is not a substrate

The earlier analysis sorted platforms by one test: does the product give an agent a Linux filesystem, network and arbitrary binaries for the length of a run. Entire fails it by design. The CLI attaches through hooks to an agent running on a laptop, a CI box or a cloud container, and "Entire needs captured session context and a Git commit to create a normal committed checkpoint" ([Docs: Capture checkpoints](https://docs.entire.com/guides/checkpoints/capture-checkpoints.md)). The forge post states that "Coding agents are the developer's own" and that Entire runs its review agents "using Claude Code and Codex in isolated cloud sandboxes provided by Daytona and E2B" ([Forge post](https://entire.com/blog/the-git-forge-for-agent-human-collaboration)). Those Trail agents "are configurable AI jobs that review changes in a Trail and evaluate them", started by a Trail push, by hand, or on a **recurring schedule**, and configured with harness, model, effort, timeout and instructions ([Docs: Trail agents](https://docs.entire.com/guides/trails/agents.md)). The page says reviewers "push fixes for another evaluation" but does not say a Trail agent can take a task and write code; the marketing page says agents "can loop until evals pass" ([entire.com](https://entire.com/)), and no documentation page describes Entire running that coding loop. Whether Trail agents can be configured to write and push code is an open fact.

That places Entire beside the earlier report's builders in one respect and apart from them in another. Like Dify, n8n, Dust and StackAI, it has a scheduler and a sandbox that are not a place to keep a long-running clone; unlike them, it is not sold as a general automation front end. Its scheduled jobs review; tsk's robots claim a task and produce commits. For an unsupervised coding robot, the runtime does not change: the robot runs in a Claude Code cloud session started by a routine, the baseline that the earlier report found to be the only substrate where tsk's full model is documented end to end, and the Entire CLI is one more tool that the SessionStart hook installs and enables with `entire enable --agent claude-code`. The robot gains a reviewer it does not have today. Entire's Trail agents, run against a robot's branch, give a scored second opinion on each push, which bears on the main weakness of unsupervised work: nobody reads the commits as they land.

## Entire duplicates the trace-back and lacks the ledger

The overlap with tsk is narrow and deep. tsk puts a session-ID trailer on each commit that points at a Claude Code session URL, which a reader cannot query offline. Entire puts a checkpoint ID on each commit, "Each commit gets its own checkpoint ID", and the checkpoint holds prompts and responses, tool calls and shell commands, file changes, "time-stamped agent and model metadata" and "line attribution between agent and human edits" ([Docs: Sessions overview](https://docs.entire.com/guides/sessions/overview.md)). One session can produce several checkpoints and one checkpoint can draw on several sessions. On trace-back, Entire is the stronger tool. Continuation overlaps only in part. `entire session resume BRANCH` "finds the session ID from checkpoint-linked commits on that branch", checks out the branch, "restores the session log if needed" and starts the same agent harness ([Docs: Resume](https://docs.entire.com/guides/sessions/resume-sessions.md)), and Dispatches summarise sessions, checkpoints and commits "for team updates, reviews, and handoffs" ([Docs home](https://docs.entire.com/)). The resume page does not say whether resume works on a different machine, such as a fresh cloud container, which is the only case a tsk robot meets. tsk's continuation entry is a different object: a written hand-off on a thread, independent of the agent harness, that a different actor reads and acts on.

| tsk function | Entire | Assessment |
|---|---|---|
| Commit to session trace-back (trailer) | `Entire-Checkpoint` trailer to a stored transcript, `blame`, `why`, `search` | Duplicated and exceeded |
| Agent state synced over git refs | Checkpoints as git trees on `refs/entire/` or `entire/checkpoints/v1` | Both, different contents; Entire has no relational store |
| Continuation state and hand-off | Resume of a transcript and branch for the same harness; Dispatches | Partial; cross-machine resume unstated |
| Missions, objectives, constraints | Trails hold a goal, decisions and discussion as free text tied to a merge | Absent as typed records |
| Tasks with claims, open questions, decisions as records | No source shows a task queue, a claim or an open question object | Absent |
| Actors, robot identity, instances, thread bindings | Sessions identified by agent name and git author; orgs, projects, grants for teams | Absent |
| Review gates, eval scoring, cross-repo change tracking, hosted git | Trails, Trail agents, CI partners Buildkite and Depot | Entire has them; tsk does not |

The table rests on the notes' synthesis of the documentation pages cited above. The gap that matters most is the claim. tsk's coordination depends on a robot marking a task `in-progress`, publishing that claim, and other actors seeing it before they start; Entire has no object for that, so two agents under Entire alone can start the same work and only find out at review. Trails are the nearest thing to a mission, and they sit at the other end of the work: a Trail describes a change on its way to merge, while a tsk mission describes work before anyone writes it.

## Used together, Entire is the record of how and tsk the record of what

The two compose with low coupling, because Entire adds to existing git hooks and adds no commits ([README](https://github.com/entireio/cli)). A sketch, built from the notes' inferences rather than from a tested setup: the repo's SessionStart script installs the CLI and runs `entire enable --agent claude-code` with the branch backend; `.entire/settings.json` sets `"commit_linking": "always"` so a robot's commits link without a prompt, since "Commits made by the agent go through the same Git hooks" ([Docs: Capture](https://docs.entire.com/guides/checkpoints/capture-checkpoints.md)); and tsk, at `thread pause` or `thread stop`, reads the `Entire-Checkpoint` trailers of the thread's commits and stores the IDs in the continuation entry, so the next actor can run `entire checkpoint explain <id>` before it resumes. The division of authority then stays clear: the ledger records what work exists, who holds it and what was decided; Entire records how each commit was produced. Programmatic access exists for a deeper link, through `entire search --json`, `entire api`, an MCP server and OpenAPI specs for Git, Sessions, Trails and Webhooks, and any `entire-<name>` executable on `$PATH` is a plugin ([README](https://github.com/entireio/cli); [Docs index](https://docs.entire.com/llms.txt)). An `entire-tsk` plugin, or Entire webhooks fed into tsk's event queue to tie a Trail to a mission, is possible on those interfaces but speculative. This is also the HTTP MCP front end that the earlier report recommended for tsk: with it, a Trail agent could read the mission and task behind the branch it reviews.

The risks fall into four groups. The first is the push rule. The default backend pushes `refs/entire/checkpoints/*`, which the Claude Code cloud proxy refuses for the same reason tsk keeps its ledger on `refs/heads/tsk/*`; the branch backend, `entire/checkpoints/v1`, sits under `refs/heads/` and should pass, or a separate checkpoint repository can take the data ([Docs: Session storage](https://docs.entire.com/guides/checkpoints/checkpoint-storage.md)). The notes mark this as inference, not tested. The second is privacy. Redaction runs in nine layers, but the ninth, the "OpenAI Privacy Filter", runs only on the branch backend at push time, shadow branches hold "raw, unredacted working-tree snapshots" locally, and the docs say to "Treat redaction as a safety net rather than a guarantee" ([Docs: Security](https://docs.entire.com/security.md)). A full transcript of an unsupervised robot, with whatever secrets passed through its shell, then sits in a shared repository. PostHog telemetry is on by default ([Docs: Security](https://docs.entire.com/security.md)). The docs state that "Entire does not operate a service that receives your transcripts", but entire.com reads checkpoints through its GitHub App, a secondary source reports that checkpoints sync to a Supabase database "only for display" ([36Kr](https://www.36kr.com/p/3678623948366473)), unverified, and the statement holds only while the git remote is not Entire's own forge. The third is hook overlap. tsk's plugin already uses SessionStart, Stop and SessionEnd hooks to bind threads and publish the ledger, and Entire installs its own Claude Code hooks plus pre-push and commit hooks; whether the two sets coexist without conflict is untested, and every `git push` would carry a second ref namespace and a growing body of transcripts. The fourth is direction. The February promise to "evolve Checkpoints into shared memory so agents can coordinate and hand off work" ([Hello Entire World](https://entire.com/blog/hello-entire-world)) aims at tsk's ground, and the October line "The repository is the only memory your agent should need" ([Forge post](https://entire.com/blog/the-git-forge-for-agent-human-collaboration)) points to a future in which Entire's coordination features assume Entire's forge. The notes infer, without evidence beyond the product sequence, that the open CLI can become the less maintained part. Reception at launch was split between interest in "the checkpoint primitive" and scepticism of "a brand new paradigm just because LLMs evidently suck at sharing context in their Git commits" ([HN item via Algolia](https://hn.algolia.com/api/v1/items/46961345)), and a free alternative, Claude Code conversations as Git Notes, appeared the next day ([Algolia search](https://hn.algolia.com/api/v1/search?query=entire.io&tags=story)).

## Conclusion

Entire is the first product in this research that works on the same object as tsk, git refs holding agent state beside the code, rather than on a runtime or a scheduler. That makes the relation sharper than with the earlier four platforms: tsk does not run on Entire, and Entire does not call tsk, but the two write to the same repository and both read commit trailers. The most useful outcome for tsk is to treat Entire's checkpoint as the transcript store it does not have and to keep its own ledger as the one place where claims, decisions and hand-offs live, linking the two by checkpoint ID. The trailer tsk writes today becomes an index into a richer record, and the continuation entry gains evidence a reader can query offline.

The strategic signal runs the other way. A well-funded company has named "intent, constraints, and reasoning" in a git-compatible database as its goal, and Trails already carry goals and decisions. If Entire adds claims and open questions to Trails, it covers most of tsk's coordination model for teams that accept its forge. tsk's position against that is the one the earlier report reached for portability: a ledger that runs on any remote and any substrate with a shell, under the proxies' branch-only rule, with an MCP interface that a forge's agents can read. The facts to settle before any integration are small: whether the branch backend pushes through the Claude Code proxy, whether Entire's hooks and tsk's run side by side, and whether `entire session resume` works in a fresh container.
