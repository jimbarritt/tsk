This release makes `tsk nexus move-ledger` all or nothing and warns about a custom ref in a cloud session. It also keeps a session's identity through `tsk ledger discard` and explains a GitHub private email error.

- `tsk nexus move-ledger` checks both refs in the nexus before it pushes anything. It then pushes the data ref and the documents ref in one atomic push. After a failed run the nexus is unchanged. When a push or the registration of the entry fails, the command removes the refs this run created. It names the delete command for any ref it cannot remove. When registering the entry reports an error but the nexus entry already has the ledger, the command keeps the refs. It prints a warning and completes the transfer.
- `tsk nexus move-ledger` stops before any push when the nexus contains an old layout name (`ledgers/<id>`, `ledgers/<id>-docs`) or a backup ref (`ledgers-backup/<id>/...`) of the same id. The error names each ref and the `git push <nexus> --delete` command. The "does not overwrite a ledger" error names the same command. Each message states that a person runs the command in a terminal. The ledger guard blocks the command for an agent, which must stop and report it.
- In a Claude Code cloud session with custom refs, `tsk ledger status` prints a `warning:` line in the `Ledger` block before any record is written. The remedy depends on where the choice came from: the environment, the nexus entry or the repo config. For a ledger that origin already has on custom refs, the warning advises a push from outside the cloud or `tsk nexus move-ledger`.
- `tsk ledger discard --yes` keeps this session's thread binding and robot, and writes them back when origin lacks them. Earlier the Stop hook prompted for a robot and a thread again after a discard. A binding to a thread that origin lacks is not kept, and the command prints a line for it. A store error while the identity is written back no longer fails the command. The discard is complete, so the command prints a warning and exits 0. An actor skipped because origin has another actor of the same name gets no session row.
- A push that fails on GitHub with GH007 (a private author email) stops at the first attempt. The error names the local commits whose author or committer email is not a noreply address. It lists their short hashes, emails and subjects. Earlier a branches ledger retried ten times and a custom ref ledger reported that the host accepts only branches.
- Session start and the `tsk` skill instruct the agent to put a sensitive or private input document in the folder that `tsk ledger scratch` prints. Examples are a transcript, a chat and a web page.
- The plugin is at 0.3.70. `tsk thread session-start` asks for the plugin update where an older plugin is installed.
