Far fewer round trips and process launches, and an automatic update when the ledger is newer than tsk.

Measured on a scratch copy of this repo's ledger (125 Dolt table files), median of 3 runs. "330 ms" adds 330 ms to every network operation, which matched the live origin within 1% in the research. Full table: `docs/arch/2026-10-19-m-perf-results.md`.

| Command | 0.17.0 (330 ms) | 0.18.0 (330 ms) | 0.17.0 (local) | 0.18.0 (local) |
|---|---|---|---|---|
| `tsk ledger status` | 1.76 s | 0.60 s | 0.97 s | 0.28 s |
| `tsk ledger fetch`, nothing new | 2.12 s | 0.51 s | 1.06 s | 0.16 s |
| `tsk thread session-start` | 2.62 s | 0.53 s | 1.45 s | 0.18 s |
| `tsk thread list` | 6.41 s | 0.65 s | 4.89 s | 0.29 s |
| `tsk thread pause` | 7.94 s | 3.47 s | 3.81 s | 1.28 s |
| `tsk thread start` | 7.39 s | 3.63 s | 3.67 s | 1.52 s |
| `tsk ledger push`, a change | 4.81 s | 3.36 s | 1.95 s | 1.23 s |

Record reads and writes (`mission list`, `task add`, `task set`) are unchanged at 0.1 to 0.3 s. Output is byte for byte the same as 0.17.0 over a script of 90 commands, errors and exit codes included.

- **An up-to-date check.** A refresh, `tsk ledger status`, `tsk thread list` and `tsk thread session-start` first run one `git ls-remote` of both ledger refs. When both tips match the tips last fetched, they skip the Dolt fetch and the documents fetch. The tips are recorded in `<state>/repos/<clone-id>/remote-tips` after each successful fetch. When the check fails, they fetch as before.
- `tsk ledger status --local` makes no network call and prints `Origin  not checked (--local)`.
- **One fetch per command.** A command no longer fetches again just before its push. The push relies on its own rejection when the remote moved, then fetches and retries. A test has a second clone push between a command's refresh and its push, and both changes survive.
- **Fewer `dolt` processes.** A thread write reads its snapshot in one process and writes in one more. `tsk thread list` runs 2 processes, from 38.
- `tsk thread pause` checks the local remote-tracking refs for the code commit first, and fetches the code repository only when they cannot confirm it. A branch deleted on origin keeps its local ref until the next fetch prunes it.
- `TSK_NO_BATCH=1` makes every batched read and write take the old query-by-query path. Tests run the old path against the new one.
- **Automatic update.** When a command stops because the ledger layout is newer than this tsk supports, tsk warns, runs the same update as `tsk self-update`, and runs the command again with the new binary. It never runs from the hook commands, it has a loop guard (`TSK_AUTO_UPDATED`), and `TSK_AUTO_UPDATE=never` turns it off. Only the exact unsupported-layout error triggers it. A tsk newer than the ledger upgrades the ledger on its first write, never on a read. Binaries released before 0.18.0 cannot do this.

Not met: a thread command under 1 s on a local origin. `thread start`, `pause` and `resume` take 1.3 to 1.5 s there. 0.75 s of it is Dolt's own push. Only a smaller remote reduces that, which is M-PERF T-05 and T-06.
