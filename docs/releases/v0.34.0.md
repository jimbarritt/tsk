Install and first-run polish from the field test M-TSK-FIELD (M-TSK-ADHOC T-09, T-10, T-11, T-12, T-13, T-14, T-15, T-17, T-18, T-19, T-20, T-23). The ledger is still at layout 10.

- **`tsk doctor`.** Checks the `tsk` files on PATH, `dolt` 2.5.0 or later, `jq`, `git`, the git repo, the origin remote, the ledger refs, the plugin version against the binary, the Xcode licence on macOS and the Dolt server. It prints `ok` or `FAIL` for each check and the fix for each fault. Exit 0 when all pass, 1 when any fails.
- **Several `tsk` on PATH.** `tsk doctor` lists each with its version and names the one that runs. `tsk self-update` prints the same note. A stale copy was the cause of the field-test report that `tsk ledger status` was an unrecognised subcommand: `ledger status` first shipped in 0.12.1, and the machine ran 0.2.1 from `~/.cargo/bin`. The README Install section says a stale copy shadows a new one.
- **`tsk --help`.** It opens with what tsk is and how to start, groups the commands by what a person does, and points to `tsk <command> --help`. A test checks that it names every command. It states that `tsk install-plugin claude-cli --plugin tsk --plugin swe` installs the swe plugin at project scope, and that `claude plugin install` alone defaults to user scope.
- **`tsk install-plugin`.** With no target it prints the help, which lists `claude-cli` and `copilot-cli` with examples. Outside a git repo it stops with exit 1 and says tsk works per repo and to run it inside the repo that will use tsk. It prints the repo it installs into, and ends with a summary: what is installed and at which scope, what happened to `.claude/settings.json`, when to commit it, how to start, and that the first `tsk ledger push` creates the ledger.
- **Empty lists.** `tsk mission list`, `task list`, `decision list` and `question list` print one line on stderr when they have nothing to list, such as `no missions yet: create one with tsk mission create, or run tsk thread start`. Stdout stays empty, and `--porcelain` prints nothing.
- **`tsk ledger status`** ends with a `Ledger` block: the ledger store path, the refs in use and where the choice came from, and the counts of missions, tasks, threads and actors.
- **`tsk mission show <id>`** prints one mission as plain text: purpose, decision authority, objectives, constraints, out of scope, blockers, tasks, decisions, open and answered questions, and documents. It prints the data of `mission list <id> --json` and adds no field.
- **Agent rules.** The session start context and the tsk skill tell an agent in any repo to check the ledger with `tsk ledger status`, not to run `ls`, `find` or `git` against the ledger store, and not to pipe `tsk` through `head` or `tail`. Plugin 0.3.30.
- The plugin requires tsk 0.34.0 or later.
