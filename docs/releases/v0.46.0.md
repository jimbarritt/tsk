Robot commit signing in a cloud session (M-TSK-ATTRIB T-13). `tsk actor git-identity` makes commits sign with the robot key and keeps the identity of each worktree apart. The ledger stays at layout 14, and the plugin stays at 0.3.45.

- **`tsk actor git-identity` writes `gpg.ssh.program=ssh-keygen`.** The cloud image sets a platform signer in the global git config, which ignores `user.signingkey` and signs with the platform key. The repo setting makes git call `ssh-keygen` with the robot key file.
- **The settings go to the worktree, not the clone.** The command sets `extensions.worktreeConfig` and writes with `git config --worktree`, so the settings are in `config.worktree`. Two robots on two worktrees of one clone keep their own name, email and key. Settings from an earlier run stay in `.git/config`, and the worktree file takes precedence.
- **`ssh-keygen` must be installed.** Add `command -v ssh-keygen >/dev/null || apt-get install -y openssh-client` to the setup script of the cloud environment.
- User guide: [docs/user-guide/robot-commit-signing.md](../user-guide/robot-commit-signing.md).
- Tests: the attribution unit tests. A manual test in a cloud session: a plain `git commit` signs with the robot key and verifies as `G` against its public key, and two worktrees of one repo keep separate `user.name` values.
