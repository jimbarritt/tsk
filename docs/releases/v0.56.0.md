Every ledger commit has the robot identity when robot attribution is on.

- **Git commits.** A commit on the ledger data ref and on the documents ref, and a rebase of one, has the robot name and email as author and committer, and the SSH signature of the robot key. `GIT_AUTHOR_*` and `GIT_COMMITTER_*` from the platform do not replace it.
- **Dolt commits.** A commit in the ledger store has the robot name and email, through `DOLT_AUTHOR_*` and `DOLT_COMMITTER_*` for a `dolt` process and the session variables of the Dolt server. Dolt has no SSH signing.
- **One function.** `ledger_identity` in `attribution.rs` returns the identity from the git config of the code worktree, which the session start and `tsk actor register` write. It returns nothing for the `default` identity.
- **Stop with no robot actor.** With robot attribution on, a ledger commit stops with an error until a robot actor is registered. No commit uses a fallback name (decision of M-TSK-ATTRIB T-19).
- **Tests:** an integration test with robot attribution on: the commit stops before registration, then a commit on the data ref has the robot name and email and `%G?` prints `G`, and the Dolt commit has the robot name and email. Unit tests for the options and the environment.
