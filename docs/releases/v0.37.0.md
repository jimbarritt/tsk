Robot commit attribution (M-TSK-ATTRIB T-04, T-05). The ledger is still at layout 10.

- **A setting chooses it.** `[attribution] identity` is `default` or `robot`, `default` when unset. With `default`, tsk writes no git config. `[attribution] email` has no built-in value. Both keys can be in `.tsk/config.toml` or the user config. `identity` is read from the repo config, then the user config. `email` is read from the environment variable `TSK_ATTRIBUTION_EMAIL`, then the repo config, then the user config.
- **`tsk config attribution`** prints the settings and where each came from. `tsk config attribution robot --email <address>` writes them to `.tsk/config.toml` and keeps its other keys and comments.
- **`tsk actor git-identity`** writes `user.name`, `user.email`, `gpg.format`, `user.signingkey` and `commit.gpgsign` to the repo's local git config, from the registered robot, the `email` setting and the private SSH key in `TSK_ROBOT_SIGNING_KEY`. The key goes to a file with mode 0600 in the state directory of the clone. A human actor and the `default` identity change nothing. With the `robot` identity and no email, or no key, the command exits 1 and names the missing setting.
- **It runs by itself.** `tsk actor register` runs it after a registration, and `tsk thread session-start` runs it when a session starts, because a new container has no local git config. A failure is a warning, and commits keep the default author.
- Plugin 0.3.38: the construct-robot skill describes the step. The plugin requires tsk 0.37.0 or later.
- Guide: `docs/user-guide/robot-commit-signing.md`.
- Tests: unit tests in `cli/src/attribution.rs` for the precedence, the config write, the key and the git settings.
