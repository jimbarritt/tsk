A git hook of the code repo no longer stops `tsk ledger push`, and a repo can check its ledger documents through a hook point of `tsk` (ADR 0025). The ledger is still at layout 9.

- **Git hooks are off for the ledger.** The documents worktree and the ledger transport worktree are linked worktrees of the code repo, so git ran the code repo's hooks for the commits and pushes `tsk` made there. A `pre-commit` hook (the one `/swe:install-commit-hook` writes, say) stopped `tsk ledger push` before it pushed anything. Every git process `tsk` starts for the ledger now runs with `core.hooksPath` set to an empty path (through the `GIT_CONFIG_COUNT` environment entries, so the arguments stay the same), and no git hook runs. The `Git` helper of `cli/src/ledger/git.rs` sets it in one place.
- **A documents hook point.** An executable `pre-docs-commit` script runs with the documents worktree as the current directory, `TSK_DOCS_WORKTREE` set to its path, and the changed document paths (relative to it) as arguments. It runs after `tsk ledger doc put <path>`, with that path, and before `tsk ledger push` and the background publish commit the documents, with every document changed since the last push. A non-zero exit makes the command exit 1 and prints the hook's output. After a failed `doc put` the document stays written locally. A failed push pushes nothing and keeps the local state. `tsk` has no dependency on any lint tool and names none.
- **Four places for the hook, and the first that exists wins.** The file `TSK_DOCS_HOOK` names; `<state>/repos/<clone-id>/hooks/pre-docs-commit`; `${XDG_CONFIG_HOME:-$HOME/.config}/tsk/hooks/pre-docs-commit`; `.tsk/hooks/pre-docs-commit` in the repo. A person who cannot commit a file to a repo uses one of the first three. A place with no file is skipped. A file that is not executable is an error that names its path. **`tsk config docs-hook`** prints the script that applies and the place it came from, or `docs hook: none`.
- **`TSK_SKIP_DOC_CHECK=1` skips the hook** at both points, and `tsk` says so on stderr. A hook file that cannot start is an error that names its path. No file means nothing runs.
- **A failed background publish shows its cause.** The failure text of a git command now includes its stdout as well as its stderr, because a git hook writes its findings to stdout. The warning of the next command shows the first 20 lines of the error, with the hook's output for a hook failure. A one-line error reads as before; a longer one shows under the first line, indented, with the line `Run tsk ledger push` after it.
- **The race tests use a `git` shim.** The tests in `ledger.rs` and `transport.rs` that landed a commit from a `pre-push` hook of the code repo, to race a push, put a `git` shim first on `PATH` instead (`common::install_git_shim`), because `tsk` no longer runs that hook.
- Tests: `cli/tests/background/doc_hook.rs` (a failing git `pre-commit` and `pre-push` hook does not run for `doc put` and `push`, a failing documents hook stops `doc put` and the push and the document stays, a passing hook gets the paths, the directory and `TSK_DOCS_WORKTREE`, the skip variable, a hook that is not executable, the order of the four places, `tsk config docs-hook`, and the warning of a failed background publish for a hook and for git), and unit tests of the hook runner, the git helper and the warning text.
