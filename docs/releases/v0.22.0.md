A thread pause takes 0.88 s through a 330 ms network shim. It took 1.42 s. The figures come from one machine at a load average of 9 to 10.

- **A pause, a thread start and `tsk ledger push` do not ask origin first.** The clone's record of the last fetch stands in for what origin holds. A push of a clone whose record is out of date is rejected and retried after a fetch, as before. A pause or a start whose checks fail on the recorded state runs them again on a fresh fetch, so an error is always about what origin holds. `tsk thread resume`, `tsk thread list`, `tsk thread session-start` and `tsk ledger fetch` ask origin as before.
- **Fewer `dolt` processes in a push.** The write of a pause, the staging, the commit and the reads that open the push run in one process. A pause starts 3 `dolt` processes where it started 5. A push with a change starts 3 where it started 4, and a push with nothing to send starts 2 where it started 3.
- **A refresh reads its database while it asks origin.** The question to origin waits for the network. The reads of the database wait for nothing, so they run at the same time. A session start with nothing new takes 0.39 s through the shim, where it took 0.52 s. When origin has something new, the reset to the fetched state and the reads after it run in one process.
- **A new clone fetches both refs in one `git fetch`.** A clone with no ledger store, or no record of a fetch, used to ask origin, then fetch the ledger ref, then fetch the documents ref. It now fetches both refs at once into `refs/tsk-fetch/ledger` and `refs/tsk-fetch/docs`. A fresh cloud session start takes 0.88 s through the shim, where it took 1.55 s. If origin lacks one of the refs, the old question follows.
- **The SessionStart hooks start fewer processes.** `plugin/hooks/install-dolt.sh` records a passed version check in a stamp file and reads the dolt user name and email from `~/.dolt/config_global.json`, so a session start no longer starts `dolt` three times for each of two hooks. `ops/local/claude-session-start.sh` adds and refreshes the marketplace once for both plugins, runs the plugin steps while the dolt check and the tsk session start run, and skips the plugin steps for 60 minutes after a run with no warning (`TSK_PLUGIN_ENSURE_MINUTES` sets the time; `0` never skips).
- **The pause-thread skill reads the binding with `tsk thread binding --no-fetch` and checks the ledger with `tsk ledger status --local`.** The whole skill flow makes one network operation where it made five. The plugin is 0.3.13 and requires tsk 0.18.0 or later.
- **A rejection of the first push on the record of the last fetch is not said aloud**, and its retry does not wait. The old flow found that origin had moved by asking, and printed nothing. A second rejection prints the note as before.
- The new methods are internal. `LedgerStore` gains `trust_last_fetch`, `distrust_last_fetch` and `continuation_append_deferred`.
- Update every `tsk` and the plugin together. A `tsk` older than 0.22.0 works against the same ledger.
