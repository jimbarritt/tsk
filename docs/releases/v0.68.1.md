A Homebrew self-update fix, commands that edit `nexus.json`, and a push workflow that `tsk harness new` states in the first prompt.

- **Self-update on Homebrew.** `tsk self-update` on a Homebrew install runs `brew update`, then `brew upgrade`, then reads the installed version. It exits non-zero when that version differs from the target. A stale local tap made it report success while nothing changed.
- **Nexus commands.** `tsk nexus` edits `nexus.json` on the default branch of the attached nexus, then commits and pushes. `add-territory`, `rename-territory` and `remove-territory` edit territories. `set-repo` takes `--workflow main|pull-request`, `--prefix` and `--url`. `move-repo --territory <id>` changes the territory of an entry, and `remove-repo` deletes an entry. A repo entry has an optional `workflow` field. For example, `tsk nexus set-repo my-repo --workflow pull-request`.
- **The push workflow.** The first prompt of `tsk harness new` states how the repo takes changes, main or pull request. `tsk` reads it from the `workflow` field of the nexus entry, then from `[harness] workflow` in `.tsk/config.toml`. When neither has a value, it puts the question "Push to main or open pull requests?". It saves the answer with `set-repo`. `--push main|pr` answers the question and is not saved. `tsk harness wake` writes the same prompt. For example, `tsk harness new --push pr`.
- **Documents.** The user guide page on moving a thread from the cloud to a terminal has lint fixes. It also describes the push question.
