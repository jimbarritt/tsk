A cloud session offers only the robots that no open session uses.

- **Taken robots.** A robot is taken while any cloud session it ran in is not archived, idle sessions included. It stays taken until its session is archived.
- **`tsk thread next --open <id>,...`.** Takes the IDs of the cloud sessions that are not archived. A robot whose registrations or sessions name one of them is not offered, and the prompt names it as taken. With every robot taken, the prompt asks to construct a new one. A session ID matches its harness instance: `session_X`, `cse_X` and `cloud:cse_X` are one session.
- **Cloud and terminal.** In a cloud session (`CLAUDE_CODE_REMOTE=true`), `tsk thread next` and the Stop hook without `--open` print one step: call `list_sessions` (mine, limit 100) and run `tsk thread next --open` with the sessions that are not archived. In a terminal there is no list of sessions, so every robot is offered, as before.
