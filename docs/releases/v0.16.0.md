The files ledger backend and the daemon-era code are removed.

tsk is committed to Dolt. Every release up to and including v0.15.1 contains the files backend, and `archive/tsk-ledger-files` holds the history of the file ledger.

- **The files (git) backend is removed**, with `tsk ledger migrate-to-dolt` and the `[ledger] backend` setting. `[ledger] backend = "git"` or `TSK_LEDGER_BACKEND=git` now stops with `error: the files ledger backend was removed in 0.16.0; use tsk 0.15.1 to read an old file ledger`. A ref that still holds a file ledger stops with an error that points to 0.15.1's `migrate-to-dolt`. `tsk ledger migrate-docs` stays. ADR 0015 records the decision and supersedes decision 2 of ADR 0014. The `LedgerStore` trait stays, with one implementation. A ledger held in a nexus repo is covered by a new conformance case.
- **The daemon-era code is removed** (ADR 0012): the TUI, the `tskd` daemon and the old `tsk-core` model. `tsk` with no arguments prints the help to stderr and exits 2. The release pipeline publishes `tsk-bin` only; `tsk-core` 0.15.1 and earlier stay on crates.io. The three `docs/arch` documents about the daemon design are marked historical.
- The conformance suite runs each case once, on Dolt. The workspace has 524 tests, from 710.
- Documents: `docs/arch/2026-10-18-remote-growth-design.md` (why a fetch costs what it does, and the options), `docs/arch/2026-10-18-documents-in-dolt-comment.md`, and the 2026-10-17 architecture and performance review.
