`tsk nexus register-repo` keeps the key order of `nexus.json` and creates the file on an empty nexus (M-TSK-ENV T-12 and T-13). The cloud environment guide shows an optional `tsk nexus add` step (T-14). The plugin is 0.3.53.

- **Key order.** `register-repo` rewrites `nexus.json` with the keys in the order the file already has, so a diff shows only the new entry, which goes at the end of its territory. `serde_json` has `preserve_order` on for the workspace. The repo keys of `tsk nexus list --json` now come out as `id`, `url`, `local`, `ledger`.
- **Empty nexus.** A first `register-repo` run on a nexus with no `nexus.json`, including an empty repo with no commits, creates `{"version": 1, "territories": [...]}` on the default branch with the territory that `--territory` names. Without `--territory` it exits 1. `tsk nexus list`, `tsk mission prefix` and `tsk ledger fetch` read an empty nexus as one with no territories instead of stopping with an error.
- **Cloud guide.** `docs/user-guide/new-cloud-environment.md` has an optional `NEXUS_URL` line in the setup script that runs `tsk nexus add`.
- **Tests:** a unit test and an end to end test for the key order, two end to end tests and a unit test for the empty nexus. The suite fails the same 12 tests on `main` before this release in a macOS environment: 6 `background::*`, `dolt_server::commands_that_start_at_once_start_one_server`, 5 `hooks::*` setup refresh tests.
