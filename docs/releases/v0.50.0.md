Plugins at user scope, and a cloud set-up that follows `main` (M-TSK-ATTRIB). The ledger stays at layout 14. The plugin is 0.3.51, and it requires tsk 0.49.0 or later.

- **`tsk install-plugin claude-cli` installs at user scope by default.** A user-scope install covers every repo on the machine and writes no repo hook. `--scope project` and `--scope local` still work. They print a warning first: an install at user scope and one at project scope of the same plugin make it unclear which version loads.
- **The cloud hook installs at user scope too.** `tsk thread session-start --install-plugin claude-cli` uses the same default.
- **A cloud session runs the environment's set-up again when it changed** (plugin 0.3.46 to 0.3.51). A new session starts from a disk saved after the setup script ran, and a change to `ops/cloud/setup-environment.sh` on `main` does not cause a new build. `plugin/hooks/refresh-setup.sh` compares the SHA-256 of the script on `main` with the one that last ran, and runs it again with the saved options when they differ. It also updates a user-scope `tsk` or `swe` plugin older than its release. It fetches by the commit SHA of `main`, because the CDN keeps a file under `main` for up to 5 minutes.
- **This repo's `SessionStart` script installs no plugin.** It adds a `WARNING:` line for each plugin with no user-scope install. `.claude/settings.json` no longer enables the plugins for the project.
- **The cloud setup script writes `~/.claude/AGENTS.md`** with `--use-robot-attribution`. It tells a session to ignore the platform Stop hook's advice to reset the author of a robot commit, and to push in the same turn.
- **The cloud setup script builds `cargo-edit`** for `just bump`, when `cargo set-version` is missing.
