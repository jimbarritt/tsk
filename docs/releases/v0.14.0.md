Every binding in the ledger, structured constraints, decisions that name ADRs, and a clearer `tsk ledger status`.

This release moves the Dolt ledger to layout version 8. The first write on 0.14.0 upgrades a ledger from any version from 2 up. A session that runs an older `tsk` then stops with "unsupported ledger version" until it runs `tsk self-update`. The plugin needs tsk 0.14.0.

## Bindings

- Every binding is a row in one `bindings` table, keyed on the actor: the session ID for a cloud session, and `<clone-id>/<worktree-name>` for a code worktree. The table replaces `cloud_session_bindings` and the `.git/tsk-thread-id` marker file. An existing marker file moves into the table the first time a command resolves the binding, and the file is removed.
- `tsk thread list` rows gain `actors`, the list of actors bound to each thread.
- A worktree `thread resume` or `thread detach` pushes, as a cloud one does. When the push fails, the binding is saved locally, one note says so, and the command exits 0.
- The `written_by` value on pause entries is unchanged, so two clones' main worktrees still read as one writer in the takeover warning. This is a known limit.

## Constraints and out of scope

- Constraints and out of scope are numbered lists of one-line items, like objective outcomes: `tsk mission constraint add|remove|list <id>` and `tsk mission out-of-scope add|remove|list <id>`. Numbers are never reused.
- The first write on 0.14.0 splits each old text value into items, one per non-empty line, and drops the old columns.
- `tsk mission set` refuses `constraints` and `out-of-scope`, and names the new commands. `tsk mission list <id> --json` prints both lists as `[{"n":1,"text":"..."}]`.

## Decisions and questions

- `tsk decision add --adr <path>` names an ADR in the repo, checked to exist in the working tree. `tsk decision list <mission>` prints the ADR path as a fifth column. `tsk decision list --adr <path>` finds the decisions that name an ADR across every mission, with the mission ID as a sixth column. `mission list <id> --json` decisions gain `adr`.
- `tsk question edit <mission> <q> "<text>"` rewrites the text of an open question. An answered question is refused.

## Status

- `tsk ledger status` labels a schema upgrade as one line, `data  upgrade  schema upgraded to version N (origin has M)`, in place of the `manifest` and per-table schema lines. The rows an upgrade copies between tables are hidden. Rows in tables an upgrade creates still show.
- The tsk plugin is 0.3.11.
