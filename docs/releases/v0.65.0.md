A thread has one holder, a robot is busy while it holds a thread, and `tsk actor list` is a table (ADR 0032).

- **Paused and held threads.** A thread is held when a start or a resume came after its latest pause; otherwise it is paused. `tsk thread list` prints `state` and `holder`. A resume always rewrites the binding, so a resume after a pause holds the thread again. A pause is stamped no earlier than the thread's latest binding, and an entry with no timestamp counts as a pause.
- **Take-over.** `tsk thread resume` of a thread that another harness instance holds stops with exit 1 and names the holder. `--take-over` resumes it anyway; use it when the holder no longer runs. The resume-thread skill asks the person first. Session start and `tsk thread next` say when another session holds the bound thread.
- **A robot is busy while it holds a thread.** Read from the ledger, so every place gives the same answer. A robot works in any number of sessions; a busy robot takes a new thread or no thread. The robot question lists free robots first, then busy ones, marked, and never offers a held thread. The cloud `list_sessions` step is gone; `--open` is accepted and ignored.
- **`tsk actor list` is a table.** A header row; NAME, KIND, STATE, MISSIONS, UID (8 characters) and SESSIONS (the last 3, shortened, with `+N`). `--json` adds `missions`. `--porcelain` is unchanged.
- **The liveness files** are still written, and no longer read by the robot choice.
