A robot commit names its supervising human as co-author, and a robot signs through an SSH agent.

- **Co-author trailer.** `[attribution] co_author` has the form `Name <email>`, for example `co_author = "Jane Doe <1+jane@users.noreply.github.com>"`. `tsk config attribution --co-author "Jane Doe <1+jane@users.noreply.github.com>"` writes it, and `--co-author` of `ops/cloud/setup-environment.sh` sets it for a cloud environment. With `identity = "robot"`, the `commit-msg` hook adds `Co-authored-by: Jane Doe <1+jane@users.noreply.github.com>` after the `Agent-Session` trailer, once, in a supervised session. `tsk actor join` of a human sets the worktree git config key `tsk.supervised`, and the session start clears it.
- **Agent signing.** `[attribution] signing_key = "agent:ssh-ed25519 AAAA..."` makes git sign through an SSH agent. The session start writes `user.signingkey = key::<public key>` and no key file, and ignores `TSK_ROBOT_SIGNING_KEY`. `signing_program` sets `gpg.ssh.program`, `ssh-keygen` when unset. `tsk config attribution --signing-key "agent:ssh-ed25519 AAAA..." --signing-program <path>` writes both. Ledger commits use the same program.
- **The resume step.** `/tsk:resume-thread` gains a step that runs `tsk actor join "<my uid>"` for the supervising human. The step runs before the question whether to continue. A session start clears the supervision, so a resumed session runs the step again.
- **The branch default.** With no ticket, the first suggestion of `tsk harness new` is the mission code and the harness name, for example `m-tsk-env/gurnard`. Without a mission it is the harness name. It was the mission code and the thread id.
- **Documents.** The set-up docs give the robot's commit email as the GitHub noreply address. Two new user guide pages cover moving a thread from a cloud session to a terminal, and the optional Software English commit check. `docs/domain/commit-attribution.md` names the author, committer, signer and trailers of a commit.
