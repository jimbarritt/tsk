Concurrent writers in one clone lose nothing (M-TSK-LOCAL T-07, ADR 0034).

- **The clone lock.** A command that can write takes `push.lock` of its clone at its first access to the ledger store, and keeps it until the command ends. Two `tsk task add` commands in one clone no longer take the same task number: the second one waits, then reads the first one's task. Before, the second one replaced the first task and exited 0, or failed with a Dolt serialization failure.
- **A refresh no longer resets over a write.** A refresh, such as `tsk ledger fetch`, checks for local changes and resets the store to origin under the clone lock.
- **A write no longer runs inside a push.** A write waits for a push of the same clone, and a push waits for a write.
- **Read-only commands do not wait.** The `list`, `show`, `status`, `path` and `doc get` commands, the tmux commands and the long-running harness commands take the lock only when they write, refresh or push.
- **A transaction rejected for a serialization failure runs again.** A transaction that Dolt rejects with a serialization failure runs again, up to 5 attempts, with a note on each retry.
- **Conformance cases.** `cli/tests/concurrent.rs` runs concurrent `task add` commands in one clone, concurrent writers and pushes in two clones against a local bare nexus, and concurrent fetches beside writes.
