Two clones that add to the same mission no longer collide.

- **Renumber at push.** Rows are keyed by mission and number. When two clones each add a task, question, objective outcome, constraint, out-of-scope item or decision to the same mission before pushing, both mint the same number. A push that has to merge now renumbers the pushing clone's own new rows to the next free numbers, then completes the push, and prints one line per change before the commit hash:

  ```
  T-03 is now T-05 in M-X
  Q-02 is now Q-03 in M-X
  objective 2 is now objective 3 in M-X
  ```

  The references follow the renumbered rows: the task blocks, and the task a decision names. The mission counters are set past the highest number on either side. Rows the clone did not add never move. Free text that names an old number does not change, so the printed lines are the record. Read them after a push and use the new numbers.
- A real conflict still stops the push with exit 1: two clones that change the same field of the same row. The renumbering is undone first, so the local rows keep their numbers.
- A clean push prints only the commit hash, as before. Output is byte for byte the same as 0.18.0 over a script of 328 lines.
- `tsk thread` and `tsk events` pushes print the renumber lines too.
