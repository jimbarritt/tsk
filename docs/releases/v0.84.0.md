This release adds `[attribution] signing_key_file`, which signs commits with a private key file, and raises the timeout of the Copilot guard hooks.

- `signing_key_file` names a private key file, as an absolute path or a path that starts with `~/`. Session start and the signed commits of tsk use `ssh-keygen` with that file. No SSH agent and no key copy are involved. The file must be readable by its owner only, and a looser mode is an error that names `chmod 600`.
- `tsk config attribution --user --signing-key-file <path>` writes the setting, and `--signing-key-file ""` removes it. The setting is also read from `TSK_ATTRIBUTION_SIGNING_KEY_FILE`.
- The order of precedence is `signing_key` (agent), then `signing_key_file`, then `TSK_ROBOT_SIGNING_KEY`.
- `tsk signing check` and the `Signing` line of `tsk ledger status` report the file that `signing_key_file` names. The check exits 1 when that file does not exist or its mode is too loose.
- The `preToolUse` and `permissionRequest` hooks of the Copilot plugin time out after 20 seconds, up from 5. A hook that times out lets the tool call run, so the ledger guard needs the longer limit.
- The plugin is at 0.3.74.
