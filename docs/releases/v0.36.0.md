Mission prefix check in a nexus (M-TSK-ADHOC T-32, ADR 0027 decision 4). The ledger is still at layout 10.

- **A repo cannot register without a prefix.** `tsk nexus register-repo` stops when the ledger of the repo has no mission prefix, and says to run `tsk mission prefix <PREFIX>`.
- **`nexus.json` records the prefix.** An entry has an optional `prefix` field, written at registration. Registering again records the prefix on an entry that has none, and refuses a prefix that differs from the one on the entry.
- **A prefix is unique within a nexus.** `register-repo` refuses a prefix that another entry has, and names that repo. `tsk mission prefix <PREFIX>` makes the same check when a nexus is attached. The repo's own entry does not count. Two nexuses can have the same prefix.
- Tests: `cli/tests/nexus_cmd.rs` (a refusal without a prefix, a refusal for a prefix another repo has, the prefix on a new entry, the prefix recorded on an entry that lacks it, and a second run that changes nothing). The fixture gives its repo a ledger and the prefix `WRK`.
- Plugin 0.3.32: the register-repo skill handles the new refusals. The plugin requires tsk 0.36.0 or later.
