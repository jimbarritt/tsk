`/tsk:regenerate-cloud-instance` hands over a robot name that the old session never registered (M-TSK-ADHOC T-37). The ledger is still at layout 10.

- **The fault.** The skill took the robot name from `tsk actor name` only. A session that carried a robot name in its title and had no actor registered passed no name to the new session, which then constructed a different one.
- **The fix.** With `no actor registered`, the skill takes the name from the session title (`<mission ID>: <robot name>`, or the name alone). The prompt of the new session registers the name, which joins an actor that has it or makes one, then pushes the ledger.
- Plugin 0.3.35. The plugin still requires tsk 0.36.0 or later.
