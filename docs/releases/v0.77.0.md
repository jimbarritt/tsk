This release adds `tsk ledger erase`, which removes a documents commit and its files from the whole documents history.

- `tsk ledger erase <commit>` removes a commit of the documents branch, and every file the commit added or changed, from every commit of the branch, then force-pushes the rewritten branch with a lease on the remote tip. Every version of a file the commit changed is removed, the earlier versions included. A commit that becomes empty is dropped. Without `--yes` the command prints the files and the count of commits it would rewrite, and exits 1. The documents worktree must be clean and at the remote tip. The command covers the documents only, not the Dolt data.
- After the push, the command prunes the old commits from the ledger clone, and from the remote when the remote is a directory on this machine, such as a local nexus.
- The rewritten branch has a file `.tsk-erased` that names each erased commit. A fetch or a push in a clone that still has an erased commit replaces its documents copy with the new history when the clone has no local document work, and stops with an error when it has. It never rebases onto the new history, because a rebase would replay the erased commit. `tsk ledger doc list` does not list the file.
- A tsk older than this release has no such check and can push an erased commit back. Update every clone before an erase.
