A terminal session offers only the robots that no open session on this machine uses.

- **Liveness on this machine.** Session start outside a cloud session writes `${XDG_STATE_HOME:-~/.local/state}/tsk/live/<session id>.json`: the process ID and start time of the `claude` process above the hook, found through the parent processes with `ps`, and the time. The Stop hook updates the time after each turn. `tsk session end`, which the plugin's SessionEnd hook runs, records the end. Nothing goes into the ledger.
- **An open session.** A session is open when it has not ended, and its `claude` process still runs with the same start time. With no recorded process, it is open while its last turn is within 7 days (`TSK_ROBOT_IDLE_DAYS`). A crash leaves no process, so the robot is free again.
- **tmux.** A robot that a tmux pane shows in `@tsk_actor` while the pane runs `claude` is taken too.
- **The robot choice.** In a terminal, `tsk thread next` and the Stop hook do not offer a robot whose session is open on this machine or that a tmux pane shows, and they name it as taken. Sessions on other machines are not checked. A cloud session keeps the `list_sessions` check of 0.59.0.
- **Plugin 0.3.59:** the SessionEnd hook runs `tsk session end`; the `tsk` skill describes the terminal check.
- **Tests:** unit tests for the `ps` and tmux output, the open rule, the liveness file and the terminal robot choice.
