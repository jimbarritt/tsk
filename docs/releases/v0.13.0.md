A thread can exist without a mission.

- `tsk thread start` with no mission ID mints a thread with no mission, binds this session or worktree to it, pushes, and prints `started:<thread-id>`. It gives `resume-required:<thread-id>` and exit status 2 when a binding exists, and clears `tsk thread skip`, as before. With a mission ID it behaves as in 0.12, and still refuses an unknown mission.
- A thread with no mission has no tasks. `tsk thread pause <thread-id> "" "<whats-next>"` works on it, and the entry records `mission_id` as `null`. A task ID is refused: `error: thread <thread-id> has no mission, so it has no tasks. Attach a mission with tsk thread set mission <mission-id>, or pass an empty task ID`. Tasks stay on missions. For ad hoc tasks, use an administrative mission.
- New: `tsk thread set mission <mission-id> [<thread-id>]` attaches a mission to a thread, or changes its mission, and prints `mission-set:<thread-id>:<mission-id>`. The thread defaults to the one this session or worktree is bound to. An unknown mission is refused. Earlier entries keep the mission they were written with. `tsk thread set mission --none [<thread-id>]` removes the mission and prints `mission-cleared:<thread-id>`.
- The session start context for a bound thread with no mission says `This thread has no mission, so it has no tasks.`, gives the thread's latest what's next (or `none yet`), and names `tsk thread set mission <mission-id>`. The Claude and Copilot formats say the same.
- `tsk thread list` prints `"mission_id":null` for a thread with no mission. `tsk thread resume` prints the latest entry as stored, and `{}` when the thread has none.
- The ledger layout stays at version 5. `threads.mission_id` and `threads.briefing_path` were already nullable. A file ledger thread with no mission has an `index.md` with no `Mission:` line.
- The tsk plugin is 0.3.10. Its `start-thread` skill starts a thread with no mission when the person wants continuity without one, and its `pause-thread` skill passes an empty task ID for such a thread. The skills call `tsk thread start` with no argument, which needs tsk 0.13.0.
