Agents in tmux (M-TSK-BOOT-06 T-10). The tmux session chooser shows each agent's state, mission and robot, and each tmux session takes the mission code of its thread as its name. The ledger stays at layout 14.

- **`tsk tmux install` is new.** It writes `${XDG_CONFIG_HOME:-~/.config}/tsk/tmux.conf` and adds one `source-file` line to the tmux config. The settings bind `prefix s` to a session chooser that shows, on each line, the state (`●` waits for input, `◐` works, `✗` ended with an error), the mission name cut to 24 characters, the robot name and the directory. `--print` prints the settings and changes no file.
- **`tsk tmux sync` is new.** It sets `@tsk_actor`, `@tsk_mission` and `@tsk_mission_name` on the pane in `$TMUX_PANE`, and renames the tmux session to the mission code while `@tsk_rename_session` is `on`. `tsk thread start`, `resume`, `set mission`, `detach` and `stop`, and the session start, run it. Outside tmux it does nothing.
- **`tsk tmux state <waiting|working|error|none>` is new.** It sets `@tsk_state` on the pane, and never reads the ledger.
- **The plugin's hooks set the state.** Claude Code: `UserPromptSubmit` and `PostToolUse` set `working`, `Notification` and `Stop` set `waiting`, and `SessionEnd` removes it. GitHub Copilot CLI: `userPromptSubmitted` and `postToolUse` set `working`, `agentStop` sets `waiting`, and `sessionEnd` removes it. The new script `hooks/tmux-state.sh` always exits 0.
- Plugin 0.3.44. The plugin requires tsk 0.43.0 or later.
- User guide: [docs/user-guide/tmux.md](../user-guide/tmux.md).
- Tests: unit tests for the short mission name, the `source-file` line, the pane ID check and the settings. A manual test on tmux 3.4: install into a test home, sync in a pane of this repo, and the chooser opened with `prefix s`. The full suite passes: 441 unit tests and 495 integration tests.

A ledger has a scratch directory for input documents that stay out of the ledger and out of source control (M-TSK-ADHOC T-57). The ledger stays at layout 14.

- **`tsk ledger scratch` is new.** It creates the scratch directory when it is missing and prints its path.
- **`tsk ledger fetch` creates the directory**, so every clone has it after its next fetch. `tsk ledger path` has no side effects and does not create it.
- **The directory is `<state>/repos/<clone-id>/scratch`**, beside `ledger-db` and `docs`. It is outside the Dolt database and outside every git worktree, so Dolt and git ignore it without a rule. `tsk ledger push`, `status` and `discard` do not see it.
- **Use it for** full meeting transcripts, Slack conversations and documents from the internet.
- Plugin 0.3.44. The plugin requires tsk 0.43.0 or later.
