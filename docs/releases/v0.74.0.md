This release makes four changes. A session gets the robot of its thread. A cloud session is recorded once the ledger is available. The first robot question offers an existing robot. `tsk harness wake` follows the stored push workflow.

- **A session gets the robot of its bound thread.** At session start, a session with a thread binding and no actor takes the robot that wrote the latest pause of the thread, else the last robot bound to it. The session start text then has no robot question. A thread bound to another harness instance gives no robot. A thread with no robot on record keeps the question. A session that has an actor, or that continues one from an earlier session of its harness instance, is unchanged.
- **A cloud session is recorded when the ledger becomes available.** In a cloud session the nexus cannot be read until the agent attaches it, so the session start wrote no session row and no actor. `tsk ledger fetch` and `tsk thread next` now record the cloud session and give it its actors, with the same rules as the session start. A ledger commit in that session no longer stops with `identity is robot and no robot actor is registered`. `tsk ledger fetch` prints a `warning:` line when the record fails.
- **The first question is whether to use an existing robot.** `tsk harness new`, and the session start prompt of a session with no robot and no thread, show the question "Do you want to use an existing robot (recommended)?". The existing robots are the choices, free robots first, and "Construct a new robot" is the other choice. `tsk harness new` makes a new robot with no question when no robot is registered. The `/tsk:construct-robot` skill shows the same question.
- **`tsk harness wake` reads the push workflow from the repo setting first.** The workflow in the nexus entry, else in `.tsk/config.toml`, replaces the workflow in the harness record, and the record is updated. A harness made with `--push pr` follows `tsk nexus set-repo <repo id> --workflow main`. The workflow in the harness record, which `--push` set, applies only when neither setting exists. `--push` is the fallback at wake and is not saved to the nexus entry.
