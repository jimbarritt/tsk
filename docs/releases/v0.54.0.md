A cloud session attaches the nexus repository at session start, and `/tsk:regenerate-cloud-instance` attaches every repository of a session to its replacement (plugin 0.3.54).

- **Nexus at session start.** A cloud session can read only the repositories attached to it. When a nexus is attached in the user config and the ledger fetch at session start fails, the session's opening context now has an instruction to the agent: attach the nexus repository with the `add_repo` tool, push access, then run `tsk ledger fetch` and check that `tsk ledger status` shows `(nexus)`. The context names the owner and repository from the nexus URL. Outside a cloud session, or with no nexus attached, the context is as before.
- **Regeneration.** The skill reads the repositories of the session from `get_session`. The new session starts from the first, and its prompt attaches the others with `add_repo` before it resumes the thread. The skill names no repository.
- **Cloud set-up.** `ops/cloud/setup-environment.sh --nexus <url>` runs `tsk nexus add <url>`.
- **Tests:** a unit test for the session start context.
