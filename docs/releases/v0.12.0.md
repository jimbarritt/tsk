See what is not pushed, undo it, and date a decision.

- `tsk ledger status` prints what is not pushed, one fact per line with no header: `data` and `docs` each `clean` or `local changes`, then a line per changed Dolt table (with the counts of rows added, modified and deleted) or per changed document (`A`, `M` or `D`). Two last lines, `data<TAB>remote<TAB>...` and `docs<TAB>remote<TAB>...`, say `up to date`, `ahead N`, `behind N` or `diverged ahead N behind N`, counting commits against origin. A local commit that is not pushed counts as ahead. It fetches the remote refs and changes nothing else. When the fetch fails it says so on one line on stderr, reports from what is local and prints `unknown` for the remote. `unpublished` means origin holds no such branch yet. It exits 1 only when the ledger store does not exist, and names `tsk ledger fetch`.
- `tsk ledger discard` drops every local change that is not pushed, in the data and the documents, and resets both to origin's state. It replaces `dolt reset --hard` for undoing a trial mission. Without `--yes` it prints what it would drop and exits 1. With `--yes` it fetches, resets and prints `discarded`. When the fetch fails it discards nothing. It leaves thread bindings alone. Both commands work on the Dolt ledger and the file ledger.
- `tsk decision add` takes `--on <YYYY-MM-DD>` to date a decision that was made earlier. The date must be a real calendar date: `2026-02-30` is refused. Without `--on` the decision is dated today, UTC.
- A command that needs the repository (`ledger`, `mission`, `task`, `decision`, `question`, `events`, `thread`) now stops outside a git repository with exit 1 and one line: `error: not inside a git repository. Run tsk from inside the repository whose ledger you want.` It no longer prints the `git rev-parse` message. The `SessionStart` and `Stop` hook commands still print their JSON.
- The ledger layout is unchanged. The tsk plugin is 0.3.8 and requires tsk 0.12.0 or later: its skill describes `tsk ledger status` and `tsk ledger discard`.
