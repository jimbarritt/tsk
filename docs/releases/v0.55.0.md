The session start writes the robot signing set-up before the ledger fetch, on every path.

- **Signing set-up first.** `tsk thread session-start` calls `set_up_signing` before the ledger fetch, not after the refresh. A failed fetch, such as a nexus the session cannot read, leaves the key files and the signing settings of the code worktree in place, so a commit made before the fetch is fixed is signed.
- **Attribution line on failure.** The context of a failed fetch carries the `Attribution:` line, or the signing warning, after the fetch warning. Before this release it had neither.
- **Name.** `write_name` stays after the refresh, because it reads the actor of the session from the ledger.
- **Tests:** an integration test with robot attribution on and a fetch that fails: the context holds `Attribution: robot` and the worktree config holds the email and `commit.gpgsign`.
