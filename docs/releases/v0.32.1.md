`tsk self-update` installs the release archive for a binary under the cargo bin directory, and compiles only when the archive fails (M-TSK-ADHOC T-34). The ledger is still at layout 10.

- **The fault.** `tsk self-update` chose its method from the path of the running binary. A path under `$CARGO_HOME/bin` or `~/.cargo/bin` ran `cargo install tsk-bin --locked`, which compiles the crate. In a Claude Code cloud container that holds `tsk` at `/root/.cargo/bin/tsk`, an update from 0.30.0 to 0.30.2 compiled for about 25 seconds, though the release archive exists.
- **The change.** A binary on a Cargo path takes the release archive for its platform, as a release binary does, and replaces the file. When the archive cannot be installed (no archive for the platform, no release asset yet, a failed download), `tsk self-update` prints the error and `falling back to cargo install`, then runs `cargo install tsk-bin --locked --version <latest>`. The line it prints is `updated tsk <from> -> <to> (release binary)`, or `(Cargo)` after a fallback.
- **Unchanged.** A Homebrew binary upgrades with `brew upgrade`. A binary on any other path takes the archive and stops with the error when it fails.
- **Side effect.** The records of `cargo install` (`~/.cargo/.crates.toml`) keep the last version that `cargo install` wrote. `cargo install --list` shows that version after an archive update.
- Tests: `cli/tests/self_update.rs` (`self_update_takes_the_release_archive_for_a_binary_under_the_cargo_bin_directory`: a fake `cargo` that fails is not run; `self_update_falls_back_to_cargo_install_when_the_archive_cannot_be_installed`: the fake `cargo` receives `install tsk-bin --locked --version 99.0.0`).
