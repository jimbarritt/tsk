The ledger is at layout 13: a task, a decision and a question each have a `uid` (M-TSK-ADHOC, `docs/domain/urn-scheme.md`). The ledger changes at the first write by this `tsk` that needs the new layout. A `tsk` older than 0.40.0 then stops with `unsupported ledger version 13`. From 0.18.0 a `tsk` updates itself and runs the command again. A session start never upgrades.

- **A record has a name that a renumbering keeps.** A task is `T-03` to a person, and a publish that merges can renumber it (ADR 0022). Its `uid` does not change. The upgrade fills the column from the MD5 of the kind, the mission ID and the number, so two clones that upgrade on their own write the same value; a new row gets a UUID at its first insert.
- **URNs.** `tsk mission list <id> --json` prints `urn` for each task, decision and question: `urn:tsk:task:<ledger-id>:<uid>`, `urn:tsk:decision:<ledger-id>:<uid>`, `urn:tsk:question:<ledger-id>:<uid>`. `tsk task mv`, `decision mv` and `question mv` make a new row, so a moved record has a new URN.
- Plugin 0.3.41: the `tsk` skill names the new output. The plugin requires tsk 0.40.0 or later.
- Tests: the upgrade of a layout 11 ledger on two clones now fills and compares the record uids, a case checks the URN of a record through an edit, a second task and a move, and every older layout fixture is taken through the new column.
