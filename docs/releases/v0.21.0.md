The ledger is a Dolt file remote carried by plain git.

- **Dolt never starts git.** The ledger ref holds a directory of Dolt table files. `tsk` keeps it as a linked worktree beside the ledger store and moves it with one `git fetch` and one plain `git push`. A publish no longer pays for the many round trips inside `dolt push`. The estimate is about 0.9 s against 3.4 s through a 330 ms network shim. It is not timed end to end.
- **Plain pushes only.** No force and no lease. A rejected push means origin moved, and the publish repeats from the fetch: reset the directory, `dolt fetch`, renumber and merge, `dolt push`, commit, `git push`. The limit is 10 attempts, up from 5, with a random wait of 50 to 250 ms between them.
- **New ledgers use `file-remote`.** The ref carries `.tsk-transport`. A ref without it holds the older layout, `git-remote`, which still works. `TSK_LEDGER_TRANSPORT=git-remote` makes a new ledger use the older layout.
- **`tsk ledger migrate-transport`** converts an existing ledger once. It replaces the old tree with a normal commit on top of the old tip. Every other clone moves to the new layout on its next fetch and keeps its unpushed commits.
- Update every `tsk` before anyone runs `tsk ledger migrate-transport`. A binary older than 0.21.0 cannot read the migrated ref.
- The layout version stays at 8.
- Growth is about 5 KB and 2 files per publish.
- Documents: ADR 0017.
