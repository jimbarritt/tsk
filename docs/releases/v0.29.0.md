tsk 0.29.0

## Dolt server on by default

`tsk` sends the SQL of a ledger store to a local `dolt sql-server` unless it is switched off (ADR 0018, amended). Since 0.23.0 the server was opt-in. Every command otherwise starts a `dolt sql` process, which costs 0.15 s in a cloud container and 0.95 s on a Mac for a `tsk mission list`.

- **The precedence.** `TSK_DOLT_SERVER=on|off`, then `[ledger] server = "on"|"off"` in the user config (`${XDG_CONFIG_HOME:-$HOME/.config}/tsk/config.toml`), then the default, on. `TSK_DOLT_SERVER=off` and `server = "off"` keep the 0.28 behaviour exactly: no server starts and every statement is a `dolt sql` process. `just test-server-off` still runs the suite that way.
- **A server that cannot start does not fail a command.** With no `dolt` on the path, a start that dies, or a start that takes longer than 30 s, the command runs through the `dolt` command line and prints one line on stderr, once per process: `note: the Dolt server could not be used (<reason>); running dolt directly. TSK_DOLT_SERVER=off stops tsk from trying.` A statement that the server ran and that failed is still an error.
- **`tsk config ledger-server [on|off]`.** With no argument it prints `ledger server: on|off` and the source: `environment (TSK_DOLT_SERVER)`, `user config (<path>)` or `default`. With `on` or `off` it writes `[ledger] server` in the user config and keeps the other keys and the comments of the file. The environment variable still wins over the file.
- **Mixed versions.** A `tsk` older than 0.23.0 does not know the server. Beside a running server it reads the store, and fails a write with `database is read only`. Run `tsk ledger server stop` or `tsk self-update`. 0.23.0 is the minimum for a clone that also runs a newer `tsk`: from 0.23.0 a `tsk` with the switch off stops the server when its first write fails as read only, and runs the write again. The on-disk format does not change.
- **Session start.** `tsk thread session-start` replaces a dead or stale server in the background, so a cloud session that woke from hibernation finds a live server, and the hook prints its JSON without waiting for it. It starts no server for a clone that has no ledger store yet, or for a store from before 0.21.0 that does not use a file remote.
- **Measured in the cloud container**, 0.26.0 with `TSK_DOLT_SERVER=off` against this build with the default, release builds, a scratch ledger:

  | Command | Server off (0.26.0) | Server on (default) |
  | --- | --- | --- |
  | `tsk mission list`, no server running | 0.111 s | 0.156 s (starts the server) |
  | `tsk mission list`, server running | 0.134 s | 0.016 s |
  | `tsk ledger status --local` | 0.593 s | 0.029 s |
  | `tsk thread session-start`, no server running | 0.537 s | 0.176 s |
  | `tsk thread session-start`, server running | 0.539 s | 0.061 s |
  | 224 record commands in a row | 60.5 s | 5.0 s |

  On the Mac of the field test, `ledger status --local` fell from 1.94 s to 0.89 s and `ledger status` from 2.65 s to 2.37 s.
- **Idle servers.** A server stops after 1800 s with no connection. Each uses about 90 MB while it runs.
- Tests: `cli/tests/dolt_server.rs` covers the default (on with no switch set), `off` in the environment and in the config beating the default, `tsk config ledger-server` in its three states, the fallback with one note when `dolt sql-server` exits at once, and the session start hook with the default and with a clone that has no store.
- The documents ADR 0018, `docs/domain/ledger-layout.md`, `docs/user-guide/getting-started.md`, `docs/user-guide/installation.md`, `README-AGENT.md`, CLAUDE.md and the `tsk` skill describe the new default.
- The plugin is 0.3.23 (a skill text change only) and still requires tsk 0.28.0.
