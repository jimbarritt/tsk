Robot attribution set per cloud environment (M-TSK-ATTRIB). The ledger stays at layout 14, and the plugin stays at 0.3.45.

- **`TSK_ATTRIBUTION_IDENTITY`** sets `[attribution] identity` from the environment. It outranks the repo config and the user config, as `TSK_ATTRIBUTION_EMAIL` does for the email. A value other than `default` or `robot` stops the command with an error.
- **A cloud environment turns attribution on for its own sessions** with two variables, beside the secret `TSK_ROBOT_SIGNING_KEY`: `TSK_ATTRIBUTION_IDENTITY=robot` and `TSK_ATTRIBUTION_EMAIL=<address>`. An environment without them stays at the default, off.
- **`tsk config attribution --user`** writes the identity and the email to the user config, `~/.config/tsk/config.toml`. It needs no repo.
- **This repo's `.tsk/config.toml` has no `[attribution]` table.** A clone of the repo stays off unless its environment or its user config turns attribution on.
- **`plugin/hooks/install-dolt.sh` retries the dolt download**: curl's `--retry 3` for a 5xx or a timeout, and up to three attempts for other errors. Three release runs of 0.49.0 failed on a 503, a 504 and a dropped connection from GitHub's release host.

- Tests: a unit test for the precedence of the variable. A manual test: `--user` outside a repo writes the user config, and `TSK_ATTRIBUTION_IDENTITY=default` overrides it.
