tsk 0.28.0

## Fewer agent turns at start and pause

A session in a repo with one open thread took 23 s from "hi" to the agent's reply, and `/tsk:pause-thread` took 24 s. `tsk` itself runs in under a second, so the time was in the agent's turns: each shell command and each skill load is a model turn. This release cuts the turns the skills ask for. The ledger is still at layout 9. The plugin is 0.3.21 and requires tsk 0.27.0.

- **Session start gives the resume summary at once.** For a bound thread whose mission has a record and that has a continuation entry, the context adds one sentence: the latest entry's task and its description, what is next, who wrote it and when, and a `WARNING:` when another actor wrote it. The agent writes the fixed summary from it and runs no command until the person confirms. The values are read from the local ledger store: no new network call. A thread with no mission or no entry gets the text it had before.
- **`tsk thread resume` includes the lookups.** The JSON object keeps `thread_id`, `latest` and `warning`, and adds `mission` (`{"id","name"}`, or null) and `task` (`{"id","description"}`, or null). The resume skill is one command, then the summary.
- **`tsk thread pause` verifies the hand-off.** After `paused:<thread-id>` it prints `code: clean` or `code: dirty (N files)`, `code pushed: yes` or `no`, and `ledger: pushed` or `ledger: N changes not pushed`. A check that cannot run prints `unknown (...)`. Existing lines and exit codes are unchanged.
- **`tsk thread pause --bound <task-id> <whats-next>`** pauses the thread this session or code worktree is bound to, read from the ledger store with no network call. With no binding it exits 1 and reports that nothing is bound. The three-argument form works as before.
- **Skills.** `resume-thread` and `pause-thread` are rewritten for this. The pause skill reports safe only when all three lines pass. `switch-thread` reads the mission list once instead of once for each candidate.

### Measured

Tool calls the agent needs, counted from the skill text:

| Skill | Before | After |
|---|---|---|
| resume (SessionStart context shows the thread) | 3 shell commands (`thread resume`, `mission list`, `task list`) | 0 until the person confirms, then 1 |
| resume (no context, or another thread) | 3 | 1 |
| pause | 6 shell commands on the normal path (`thread binding`, `thread pause`, `git status`, `git branch -r`, `ledger status --local`, `ledger push`), 8 with the optional `task list` and `set mission` of the compose step | 1 |

Time of the `tsk` commands in a scratch ledger (scratch HOME and XDG directories), installed 0.26.0 against this build, release profile, three runs each, in seconds:

| Command | Before | After |
|---|---|---|
| `thread session-start` (first run, then two more) | 0.58, 0.14, 0.18 | 0.57, 0.25, 0.23 |
| `thread resume` | 0.27, 0.26, 0.32 | 0.21, 0.22, 0.24 |
| `thread pause` | 0.58, 0.61, 0.56 | 0.79, 0.63, 0.65 |
| the old pause skill's other commands (`binding`, `mission list`, `task list`) | 0.43 | not needed |
| the old pause skill's verification (`git`, `ledger status --local`, `ledger push`) | 0.54 | not needed |

The commands got no faster: session start reads the latest entry, and pause reads the ledger status once. The saving is in the model turns, not in the `tsk` run time. The seconds of model time were not measured, and no model was run to time the skills. The expected effect follows from the number of turns: the resume drops from a shell command, a skill load and two more shell commands to the reply alone. The pause drops from six to eight tool calls to one.
