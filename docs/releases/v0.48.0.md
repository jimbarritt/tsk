Robot signing at session start (M-TSK-ATTRIB T-15), and the `Agent-Session` trailer (T-10). The ledger stays at layout 14, and the plugin stays at 0.3.45.

- **`tsk thread session-start` does the robot signing set-up.** With `[attribution] identity = "robot"` it writes the key file and the allowed signers file from `TSK_ROBOT_SIGNING_KEY`, the signing settings in the worktree config, and a `commit-msg` hook. It prints `Attribution: robot` in the session context. The set-up runs in the `SessionStart` hook, so no tool call of the session reads the key.
- **Any other identity removes the set-up** of an earlier robot session: the signing settings, `user.name`, the hook and the key files. A worktree config key, `tsk.attribution`, marks the settings tsk wrote. A clone set up by 0.47.0 or earlier has no marker, so its settings stay.
- **`tsk actor register` writes `user.name` only** once the session start has done the set-up. A session whose start did not run gets the whole set-up, as before.
- **`tsk actor commit-msg <file>`**, a hidden command, is the `commit-msg` hook. It removes the `Claude-Session` and `Co-Authored-By: Claude` trailers and writes `Agent-Session: <session URN>` (ADR 0029). The hook exits 0 when `tsk` is missing or older than 0.48.0. tsk does not replace a `commit-msg` hook that it did not write.
- **`ops/local/git-commit-msg.sh` is deleted.** The session start replaces its link with the tsk hook.
