`tsk ledger push` no longer stops on a link from another clone (M-TSK-VULNS T-01). The ledger stays at layout 14, and the plugin stays as it is.

- **The fault.** A push merges origin's Dolt data, and with it the links that other clones pushed. It does not bring in their documents. The next push checked those links against a documents worktree from before the merge, and stopped with `mission <id> links the document <path>, which is not on the tsk/docs branch`, although origin had the document. `tsk ledger fetch` and a second push worked around it.
- **The fix.** When a linked document is absent from the local worktree, the push fetches origin's documents, keeps local commits, and checks again. A document that origin also lacks stops the push with the same error as before.
- **Tests:** a new conformance test with two clones. One links a document and pushes. The other pushes twice, and the second push now passes and reads the document. The full suite passes: 457 unit tests and 504 integration tests.
