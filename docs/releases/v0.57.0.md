A fresh clone, and a fresh cloud session, finds its ledger through `tsk ledger status`.

- **`tsk ledger status` with no ledger store.** It prints `Local   no ledger in this clone`, the attached nexus and what it says about this repo (cannot be fetched, an entry with the ledger in the nexus or in the repo, or no entry), whether origin holds a ledger, and a `Next` line. In a cloud session an unreachable nexus gives `attach the nexus ... with the add_repo tool`; in a terminal, `check that git on this machine can fetch`. `--porcelain` prints the same facts tab-separated. `--local` prints the `Local` line only. Exit status 0.
- **No silent fallback to origin.** With a nexus attached, a repo the nexus does not list keeps a ledger that this clone or origin already holds. With neither, every ledger command stops and names `tsk ledger init`. tsk no longer creates an empty ledger on origin in that case.
- **`tsk ledger init --nexus|--repo [--prefix P] [--id I] [--territory T]`.** Creates the ledger of a repo that has none and pushes it. With a nexus attached, it first adds the repo to `nexus.json` with `ledger nexus` or `ledger repo`; the prefix is required then, and checked against the other repos. The plugin's `init-ledger` skill asks the person where the ledger goes.
- **A cloud session above the repositories.** A cloud session with more than one repository starts in their parent directory. There, `tsk` changes to the one repository below it whose origin is not the nexus, so session start and the hooks find the ledger and the binding.
- **The robot first.** With no thread binding, session start and the Stop hook list the registered robots with their threads, latest first, and ask which robot this session is, or to construct a new one. A session with a robot is offered that robot's threads, then the missions.
- **Cloud set-up.** The nexus section that `setup-environment.sh --nexus` writes to `~/.claude/AGENTS.md` says: run `tsk ledger status` and do what its `Next` line says.
- **Tests:** integration tests for the status report, the stop with no entry, a ledger kept on origin, and `tsk ledger init` in the nexus, in the repo and with no nexus; unit tests for the report, the robot-first prompt and the search below the working directory.
