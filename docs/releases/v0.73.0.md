This release fixes the upgrade gap of 0.72.0, the tmux session chooser and the start text of a resumed session.

- **Sessions that began before 0.72.0 keep writing to the ledger.** When the robot name file does not exist, tsk reads the primary robot of the session from the ledger. It writes the file and continues. As a second source it reads the robot set-up of an older tsk in the worktree config. The error for a session with no robot now names `tsk actor attach <name>` for an existing robot. For a new robot it names `tsk actor register <name> --kind robot`.
- **The tmux chooser shows the data of the right session.** The session end removes the four `@tsk_*` options from its own pane. Then it sets the session values from another pane that has a mission, or removes them. `tsk tmux sync` does the same for a pane with no bound thread and changes no other pane. The `@tsk_harness` option is not touched. The session switcher pads the session name to 24 characters since 0.72.0, which keeps a 19-character name aligned.
- **The start text of a resumed session matches the state of its thread.** The text "Do not run /tsk:resume-thread" appears only for a thread bound to this harness instance. A paused thread gets the normal paused text. `tsk harness wake` and `tsk harness new` start claude with `TSK_UNATTENDED=1`. With that variable set and a paused thread, the start text contains the instruction to run `/tsk:resume-thread` now, with no confirmation step. The wake prompt no longer contains the confirmation sentence that 0.68.3 added.
