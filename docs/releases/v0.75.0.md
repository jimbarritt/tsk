This release makes the ledger guard and the stop guard work in GitHub Copilot CLI.

- `tsk ledger guard` accepts the Copilot hook input and has a `--format` option. The guard reads `toolName` and `toolArgs` (an object or a JSON string) as well as `tool_name` and `tool_input`. Tool names match without regard to case. The tools `bash`, `edit` and `create` get the checks that `Bash`, `Edit` and `Write` get. `--format claude` (the default) prints the `hookSpecificOutput` decision. `--format copilot` prints a top-level `permissionDecision` and `permissionDecisionReason`.
- The plugin registers the ledger guard for Copilot. `hooks.json` has a `preToolUse` entry that runs `hooks/pre-tool-use.sh copilot`. A tsk older than this release exits non-zero on `--format`. The script still exits 0, so the tool call is allowed.
- `tsk thread guard` has `--format copilot`, which honours `stop_hook_active`. With a hook input that has `stop_hook_active` true, the guard prints no block. An unbound session is then blocked once, not on every stop. The Copilot `agentStop` entry passes the option. With no option, Claude Code behaves as before: the guard ignores `stop_hook_active`.
- A Copilot pane shows the waiting state for a permission prompt. `hooks.json` has a `permissionRequest` entry that runs `hooks/tmux-state.sh waiting`.
- The plugin is at 0.3.68. `tsk thread session-start` asks for the plugin update where an older plugin is installed.

The Copilot hooks are untested in a live Copilot session.
