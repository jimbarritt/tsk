Guides, skills and docs for the record model, and a warning when the plugin is out of date.

This repo's own missions are now records. The migration (M-TSK-SCHEMA T-05) moved 19 missions into the ledger, with their tasks, decisions, questions, constraints, out of scope and document links. `index.md` is retired: `tsk mission list` is the index.

- `tsk guide import` is rewritten for the record commands. It says the records are the source of truth, that documents hold free text only, how to map a plan to records, and how to read a mission in full with `tsk mission list <id> --json`. A test parses every command in the guide's command block with the real command parser.
- Session start no longer tells a session to read `index.md`. With mission records it says `Run tsk mission list to see the missions.` The unbound prompt and the fetch failure message drop the same hint.
- `tsk thread session-start --plugin-version <semver>` compares the loaded plugin with the plugin version this tsk expects. When the plugin is older, the context says so and names the update command. The plugin hook passes the flag when the binary supports it. The plugin needs tsk 0.15.0 for the warning.
- The plugin skills and README describe the current command set: no briefing paths, no `index.md`, the mission-less thread and `tsk thread skip`. The plugin is 0.3.12.
- `CLAUDE.md`, `README.md`, the user guides and the domain documents describe records and documents. The briefing template says a briefing is a projection that is not built yet.
