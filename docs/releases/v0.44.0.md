`tsk mission summary` counts the work from the records (M-TSK-ADHOC T-58). The ledger stays at layout 14.

- **`tsk mission summary` is new.** It prints the count of missions by status (`todo`, `in-progress`, `done`) and the total, then for each mission the count of its tasks by status, with a total row. It reads the ledger only and counts records, never text, so no one counts a status line by hand.
- **A parent does not roll up its children.** Each mission counts under its own status and its own tasks.
- **The forms follow `tsk mission list`.** The default prints aligned columns. `--porcelain` prints tab-separated lines with no header, each starting with `missions` or `tasks`. `--json` prints `missions`, `tasks` and `by_mission`, each with `todo`, `in-progress`, `done` and `total`.
- **`tsk mission reparent <id> <parent>` is new** (M-TSK-ADHOC T-59). It moves a mission under another parent. A numbered part takes the next free number under the new parent (`M-TSK-BOOT-03` under `M-TSK-AUTO` becomes `M-TSK-AUTO-01`) and is renamed as `tsk mission mv` does, so its tasks, decisions, questions, threads, blocks, linked documents and `uid` and `urn` follow. Task IDs stay. It prints one line per change, supports `--dry-run` and `--rewrite`, and refuses an unknown parent, a cycle and a numbered mission that has parts. References by ID in free text are listed, not changed, unless `--rewrite` is given.
