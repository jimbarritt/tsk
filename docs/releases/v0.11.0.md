Threads name their mission.

- `tsk thread start <mission-id>` takes the mission ID alone. A mission exists when it has a record, or, for a ledger not yet moved to records, a briefing document at `missions/<category>/<ID>-<slug>.md`. An unknown ID is refused with an error that names it. The old form `start <mission-id> <briefing-path>` is still accepted. The path is ignored and one line on stderr says so.
- `tsk thread pause <thread-id> <task-id> <whats-next>` takes the mission from the thread. The task ID can be empty. When the mission has a record, the task ID must name one of its tasks, and `T-5` is written as `T-01`. The old form `pause <thread-id> <mission-link> <task-id> <whats-next>` is still accepted. The link is ignored.
- A new entry carries `mission_id`. It carries `mission_link` only for a thread whose mission has no record. `task_id`, `whats_next` and the git and timestamp fields are as before. Older entries read as they were written. `tsk thread list` rows gain `mission_id`.
- `tsk thread skip` records that this session or code worktree works without a thread. The record is a file in the clone's git directory. It is never in the ledger and never pushed. `tsk thread start` and `tsk thread resume` clear it.
- The `SessionStart` context for a bound thread whose mission has a record names the mission and its open tasks, in place of the hint to read `index.md`. With mission records and no binding, the context lists the missions not done and offers them, with `tsk thread skip` as the choice for no thread. A version 1 ledger is told to run `tsk ledger migrate-docs`.
- The Stop hook check (`tsk thread guard`) passes in silence when the ledger holds no missions, and after `tsk thread skip`.
- A new Dolt ledger is manifest version 5. `threads` gains a nullable `mission_id`, and `briefing_path` becomes nullable. A version 2, 3 or 4 ledger reads as before, and its first `tsk thread start` (or mission, task, decision or question write) adds what is missing and sets version 5. A thread made before version 5 has no stored mission ID: it is derived from the file name of its briefing path when read, and never written back. A tsk from before this release stops at a version 5 ledger with `unsupported ledger version 5`: update it. `tsk ledger migrate-docs` and `migrate-to-dolt` now create version 5 ledgers.
- The file ledger names the mission on a `Mission:` line in `threads/<id>/index.md`. Its manifest stays version 1.
- The tsk plugin is 0.3.7 and requires tsk 0.11.0 or later: its skills use the new command forms.
