`tsk mission mv` moves the briefing path of a thread, so `tsk thread list` and `tsk thread title` show the new mission ID (M-ADMIN-02 T-30, now M-TSK-ADHOC T-30). The ledger is still at layout 10.

- **The fault.** A thread made from a briefing document, or before layout 5, stores the path of the document and no mission. `tsk` reads its mission ID from the file name. `tsk mission mv` renamed the document and the mission, but left the path in the thread. After `tsk mission mv M-ADMIN-01 M-TSK-IDEA`, `tsk thread list` and `tsk thread title` printed `M-ADMIN-01`, and the thread kept the old path as `mission_link`.
- **The change.** `tsk mission mv` finds every thread whose briefing path is a document the rename moves. It sets the mission of each to the new code and the briefing path to the new path. The thread then names the mission by the internal ID, so a later rename follows with no further change. It prints one `thread <id> <old path> -> <new path>` line for each, after the `doc` lines and before the `mentions` lines. A dry run prints the same lines.
- **Unchanged.** A thread that names its mission by the internal ID and stores no path follows a rename as before and has no line. A thread of another mission is not touched.
- **A thread renamed before this release** keeps the old ID. Repair it with `tsk thread set mission <thread-id> <mission-id>`.
