A terminal session updates its plugin, a bound session with no robot is asked for one, and an actor can be removed.

- **The plugin update in a terminal.** When the loaded plugin is older than the one this `tsk` expects, session start in a terminal starts `claude plugin marketplace update` and `claude plugin update tsk@jimbarritt-claude-plugins --scope user` in the background, and says the next session loads the new version. A cloud session already updates it through its set-up. `TSK_NO_PLUGIN_UPDATE` switches it off.
- **A bound session with no robot.** Session start and `tsk thread next` ask which robot the session is, from the robots no open session uses, when the session has a thread and no robot. Before, a bound session was never asked.
- **`/tsk:construct-robot` offers the free robots first.** Unless the person asked for a new robot, the skill lists the robots with `tsk actor list` and offers the free ones before it constructs a new one.
- **`tsk actor remove <name>`.** Removes an actor: its record, its name history, the instance rows registered as it and its links to sessions. Threads and pause entries stay. A local write.
- **Plugin 0.3.63:** the `construct-robot` and `tsk` skills.
- **Tests:** an integration test for `tsk actor remove`; a unit test for the robot question of a bound session.
