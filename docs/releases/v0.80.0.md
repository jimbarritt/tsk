This release adds `tsk signing check`, an agent socket setting, and a retry of an agent failure in a signed commit.

- `tsk signing check` queries the SSH agent that signing uses to check whether the robot signing key is available. It runs `ssh-add -L` with the configured socket, not the shell's `SSH_AUTH_SOCK`, and times out after 3 seconds. It exits 0 when the signing key is available. Otherwise it exits 1 and prints what to do: unlock 1Password, approve the prompt, or set the socket.
- `[attribution] ssh_auth_sock` sets the agent socket. `tsk config attribution --ssh-auth-sock <path>` writes it. A repo setting takes precedence over a user setting. On macOS the default is the 1Password agent socket when that file exists. tsk uses the socket for the signed git commands it runs and for the signing check.
- A signed ledger commit, rebase or merge that fails with `failed to fill whole buffer` or `agent returned an error` runs again, up to two more times. After the last failure the error names `tsk signing check` and states that a 1Password approval may be pending.
- `tsk ledger status` prints a `Signing` line when `signing_key` is set. The signing check inside it times out after 1 second and never fails the status.
- The tsk plugin is at 0.3.71 and the `tsk` skill lists `tsk signing check`.
