The session title shows the robot and its mission (GitHub issue #7). The ledger is still at layout 9.

- **`tsk thread title`** prints the session title for this session or worktree: `<actor name> (<mission ID>)` when it is registered as an actor and bound to a thread with a mission, the actor name alone when the thread has no mission or there is no binding, and the mission ID alone when no actor is registered. With neither it prints nothing and exits 1. It reads the ledger store as it is and never fetches, so a local write such as `tsk thread set mission` shows at once.
- **The plugin sets the title.** The `start-thread`, `resume-thread` and `construct-robot` skills run `tsk thread title` and pass the output to `set_session_title` in a cloud session, or ask for `/rename <title>` in a terminal. `switch-thread` sets it through the `resume-thread` steps. The `tsk` skill says to set it after `tsk thread set mission`.
- Tests: `cli/src/thread/ops.rs` (the four forms of the title) and `cli/tests/thread.rs` (no actor and no binding, the mission alone, the actor and the mission, and a mission switch with `--none` and back).
- The plugin is 0.3.21 and requires tsk 0.27.0.
