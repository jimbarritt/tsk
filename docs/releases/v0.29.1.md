A `tsk ledger fetch` replaces an empty local ledger with origin's (GitHub issue #8). The ledger is still at layout 9.

- **The fault.** A `tsk` command that runs in a repo before its ledger is on origin makes a new local ledger store, with only its creation commits. When another clone then publishes the ledger, origin's history has a different root. `tsk ledger fetch` left the store as it was and printed the note about commits that are not on origin, and `tsk ledger push` failed with `no common ancestor`. The way out was `tsk ledger discard --yes`, which an agent in auto mode may not run. An unattended Routine run on `jimbarritt/claude-plugins` stopped on 2026-10-24 for this reason.
- **The change.** A store with nothing to lose is replaced by origin's ledger with no prompt. The Dolt database qualifies when every unpushed commit is `Initialize data repository` or `Create the ledger`, its working set is clean and no table other than `manifest` has a row. The documents worktree qualifies when its only unpushed commit is `Create the documents branch` and its working tree is clean. The two sides are checked on their own. Every command that refreshes the ledger does this, not only `tsk ledger fetch`.
- **The note.** One line on stderr: `note: replaced an empty local ledger (creation commits only, no rows) with origin's ledger`. When only the documents branch was replaced, the line is `note: replaced an empty local documents branch (creation commit only, no files) with origin's documents`.
- **Unchanged.** Any other local commit, any row and any uncommitted change keeps the earlier behaviour: the note that names the commits, and no reset.
- Tests: `cli/tests/conformance.rs` (an empty local ledger is replaced and origin's missions and documents appear, a second fetch is quiet and a push works; a local ledger with a commit of its own is kept while its empty documents branch is replaced) and unit tests in `cli/src/ledger/store/dolt.rs` and `cli/src/ledger/fetch.rs` for the creation-commit checks.
- The plugin does not change. It still requires tsk 0.28.0 or later.
- Documents: `docs/domain/ledger-layout.md` (a ledger that does not exist yet).
