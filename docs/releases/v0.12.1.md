A readable `tsk ledger status`.

- `tsk ledger status` now prints two answers, `Local` and `Origin`, with no tab and no trailing whitespace. `Local` says `nothing to push`, or counts the changes not pushed and lists one detail line per changed table or document, with the store, the name and what changed in aligned columns (`data  missions  1 added`). Commits made and not pushed are counted after the changes. `Origin` says `up to date`, how many data and document commits are `to fetch (tsk ledger fetch)`, how many are `not on origin (tsk ledger push)`, `diverged: ...`, `not published yet (tsk ledger push creates it)` or `unknown (could not reach origin)`. A table whose schema changed and whose rows did not reads `schema changed`. The file ledger keeps data and documents on one branch, so it counts its commits once, as `ledger commits`.
- `--porcelain` on `tsk ledger status` and `tsk ledger discard` prints the tab-separated lines of 0.12.0 unchanged. Scripts and agents that parse the output use it.
- `tsk ledger discard` without `--yes` prints the `Local` block and the same error line as before. On a clean store it prints `Local   nothing to push` and exits 0.
- The tsk plugin is 0.3.9. Its skill tells an agent to parse `tsk ledger status --porcelain`. `--porcelain` needs tsk 0.12.1.
