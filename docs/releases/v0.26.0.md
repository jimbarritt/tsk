An actor is a human or a robot, with a name and a kind, and its identity persists outside any harness instance. A harness instance is the running harness: a cloud session, or a code worktree of a clone, the key that `bindings.actor` holds. An instance registers as an actor with `tsk actor register`, which is separate from binding to a thread. The ledger is at layout 9.

- **Layout 9 adds two tables.** `actors` (`name` varchar(200), primary key; `kind` enum(`human`, `robot`); `registered_at`) and `instances` (`instance` varchar(255), primary key, the same key as `bindings.actor`; `kind` enum(`cloud`, `worktree`); `actor_name`; `registered_at`). `bindings` is unchanged; its `actor` column is a harness instance key and keeps its name. The first write that reaches a binding or a registration on a layout 8 ledger creates both tables and records version 9 in the same local change. Reads upgrade nothing. A `tsk` older than 0.26.0 stops at a layout 9 ledger with `unsupported ledger version 9` and, from 0.18.0, updates itself.
- **`tsk actor register <name> --kind human|robot`.** A new name makes the actor and prints `registered <name> (<kind>)`. A name already registered must have the same kind; this session or worktree then joins it and the command prints `<name> (<kind>) is now this session's actor` or `... this worktree's actor`. The other kind is refused with exit status 1 and `<name> is registered as a <kind>`. A name is 1 to 200 characters and does not start with `/`. Needs no thread binding. A local write; the next push publishes it.
- **`tsk actor name`** prints the name of the actor this session or worktree is registered as, or `no actor registered`, and exits 0 either way.
- **`tsk actor list`** prints one actor per line: name, kind, and the instances registered as it, comma-separated, or `-`. `--porcelain` prints the columns tab-separated and `--json` prints the full records, each with its `instances`.
- **`tsk thread list`**: each entry of `actors` gains `"name"`, the actor name of that instance, or `null`. **`tsk thread binding`** prints `actor: <name> (<kind>)` on a second line when the instance is registered. **`tsk thread session-start`** adds `Actor: <name> (<kind>).` to the context when it is.
- Tests: `cli/tests/thread.rs` (register a new actor, register with no binding, join the same kind and refuse the other, the name checks, `actor list` in the three forms, the actor stays while the instance rebinds, `thread list` JSON, the session start context) and `cli/tests/conformance.rs` (a layout 8 ledger reads with no actor tables, the first registration upgrades it and keeps every binding row).
- The plugin is 0.3.16 and requires tsk 0.26.0.
