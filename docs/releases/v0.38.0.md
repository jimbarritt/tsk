The ledger is at layout 11: a row for each session, naming its harness instance (ADR 0029, M-TSK-ATTRIB T-11, T-12). The ledger changes at the first write by this `tsk` that needs the new layout. A `tsk` older than 0.38.0 then stops with `unsupported ledger version 11`. From 0.18.0 a `tsk` updates itself and runs the command again. A binary released before 0.18.0 needs `tsk self-update` by hand.

- **`sessions` table, layout 11.** A row holds the session URN, `urn:tsk:session:<harness>:<id>`, the key and kind of the harness instance the session ran in, and the start time. The harness is `claude-cloud`, `claude-cli` or `copilot-cli`. A cloud session is named by its cloud session ID. Any other session is named by the ID the harness gives its hook. `tsk thread session-start` records the session. On a ledger below layout 11 it records nothing and upgrades nothing: the first write by another command upgrades the ledger, and the next session start records.
- **`tsk session find <urn|id>`** prints the session, the URN of its harness instance and the actor. It exits 1 when no session matches. **`tsk session list [--porcelain|--json]`** lists every recorded session.
- **Instance URN.** A harness instance is named `urn:tsk:instance:<cloud|worktree>:<key>`. It replaces `urn:tsk:cloudsession:<id>` and `urn:tsk:worktree:<name>` as the fallback `written_by` value. Stored entries with the old forms stay valid.
- **Robot commit attribution, from 0.37.0.** Optional. `[attribution] identity` is `default` or `robot`, and `[attribution] email` has no built-in value. `tsk config attribution` prints and writes them. `tsk actor git-identity` writes the robot's git identity and SSH signing settings to the repo's local git config. It reads the key from `TSK_ROBOT_SIGNING_KEY`. `tsk actor register` and the session start run it. The guide is `docs/user-guide/robot-commit-signing.md`.
- Plugin 0.3.39: the `tsk` skill lists the new commands. The plugin requires tsk 0.38.0 or later.
